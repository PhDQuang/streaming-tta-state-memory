==================================================

"Add module X to YOLO and obtain slightly better mAP."

"Combine attention A with backbone B."

"Replace loss X with loss Y."

"Use optimizer X instead of optimizer Y."

"Fine-tune an existing model on another small dataset."

Such approaches are acceptable only if there is a strong scientific hypothesis explaining WHY the modification should matter and experiments can demonstrate a meaningful phenomenon.

Prefer research that investigates a real problem, mechanism, limitation, failure mode, or generalizable method.

Do NOT optimize for producing a positive result.

Optimize for discovering a scientifically defensible result.

A meaningful negative result is acceptable.

7. DEEP NOVELTY CHECK
==================================================

Take the strongest 3 candidates and perform an adversarial novelty search.

Assume initially that the idea is NOT novel.

Try to disprove novelty.

Search:

- exact method names
- synonymous terminology
- equivalent mathematical formulations
- similar losses
- similar architectures
- related training procedures
- similar combinations of techniques
- same problem on the same datasets
- same hypothesis under different terminology

Search forward and backward references where possible.

For each candidate classify the contribution as approximately:

A. potentially genuinely new mechanism or finding

B. new scientifically motivated combination of prior ideas

C. new application/domain producing a meaningful scientific finding

D. mainly engineering or parameter tuning

Strongly prefer A or B.

Category C may be acceptable when the domain-specific finding is scientifically significant.

Avoid D.

Do NOT write:

"This method is novel."

unless evidence strongly supports that claim.

Prefer cautious wording such as:

"No equivalent method was found in the literature searched so far."

Create:

research/novelty_analysis.md

Use staged experimentation.

STAGE A — Sanity Check

- reduced resolution
- small models
- few epochs

STAGE B — Pilot Experiment

Run controlled baseline vs proposed method on enough data to judge whether further compute is justified.

Before paid GPU use, report:

- proposed GPU
- VRAM
- expected GPU-hours
- estimated cost
- expected storage
- experiment matrix
- scientific question answered

WAIT FOR MY APPROVAL before spending money.

STAGE C — Full Experiment

If pilot evidence justifies it:

- full dataset
- strong baseline
- proposed method
- meaningful training schedule

STAGE D — Scientific Validation

Run:

- multiple seeds
- ablations
- robustness tests
- competing baselines
- sensitivity tests

STAGE E — Scaling

Only if scientifically meaningful, examine:

- larger backbone
- more data
- higher resolution
- stronger foundation model
- larger compute
